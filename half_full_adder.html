Half and Full Adders

We have learned about many operations involving binary numbers. However most of our lessons have involved forms or circuitry - and haven't touched on actual computer mathematics. In this article, we will be covering binary arithmetic from computer circuitry.

Binary arithmetic is essential for computers to do the operations that they do. Processing units like the ALU (Arithmetic Logic Unit) sum binary values and store them into registers. These registers store data for the CPU to register later. All systems within a computer must use some form of addition to turn numbered binary data into their analog equivalents. This necessitates the use of complex arithmetic operations like addition or repeated addition (multiplication) to convert values into computer-readable binary files.

The Half Adder

The Half Adder is a type of adder which can successfully add and output carry numbers, but it cannot process input carry operations.

  • Output carry is the evaluation of which numbers need to be carried
  • Input carry is the incorporation of a previous carry into addition

The addition of boolean literals can be compared to the logical OR operation. For the two binary digits being added, take the OR of the two bits. However a key difference is that when both digits are 1, the result must carry over to the next column. This is from the fact that 1 + 1 = 10. Therefore we have an output of 0 with a carry operation of 1.

The only way to get an output of 1 is from the XOR operation of 0 + 1. A logical gate which matches this property is the XOR gate. This creates an output which returns 1 only when 0 and 1 are added. However there is still a necessary carry operation to be constructed. The only way to carry is to add 1 + 1. The proper gate for this operation is AND. Therefore, we need circuitry which has as XOR gate when 0 + 1, and an AND gate when 1 + 1.

We can observe that A and B are wired to the inputs of the two logic gates. When A or B is 1, then the sum of the two bits will be 1. However when both A and B are 1, then the sum returns 0 while the C Out returns 1. When both bits are 0, then both the sum from XOR and the C Out from AND return 0. The structure of the half adder is nice, but there is no way use a carry.

The Full Adder

While our half adder does a good job at quick addition with minimal circuitry, it cannot be cascaded or take carry operations.

The XOR of A and B in the left-most part of the circuit is the sum. The output of (A XOR B) is then XORed with Cin to create ((A XOR B) XOR Cin). This is the final output of sum (S). Logically, this says that two things must occur for the sum to be 1. Either A or B must be 1, or there must be a carry operation from a previous input. However these operations are mutually exclusive and both cannot be done in tandem.

Analyzing the bottom part of the circuitry, there are two AND gates and an OR gate. When both (A XOR B) and Cin return 1, then it is permitted to go through an OR gate which is guaranteed to return 1 at Cout. Additionally, if both A and B are 1, then Cout is guaranteed to be 1. The logical implication of this is that Cout can occur under two occassions. When both A and B are 1, or when either A or B are 1, and Cin is 1.

Both of these conclusions make sense on a logical level. As A + B should always signal a carry operation when both values are 1. Additionally, when the XOR of A and B are 1, then combining with the 1 in Cin should carry over. As for sums, when A or B are 1 and there is no carry signal, then the sum should be 1. However if there is a carry operation, then carrying the 1 while leaving there is an existing 1 from A XOR B should leave a sum of 0.Therefore the carry operation and the Cin can be a logical 1, but must be mutually exclusive in order to return a sum of 1.

Full Adders from Half Adders

Although Half Adders cannot be cascaded, they can be manipulated in such a way that they construct adders, which can be manipulated. Taking the inputs of A and B creates both a Carry Output and a sum. The sum and Carry Input are added together in the second output to create the final sum of the two adders. Finally, if there is a carry output in both half adder 1 or half adder 2, then the carry output will be 1. However the events must mutually exclusive as per the fact that both carry outputs cannot coexist to the aforementioned.

Summary

Due to the constructions of the Half Adder and the Full Adder, we can successfully create binary addition of literals. The full adder can be cascaded by means of connecting other full adders together. We can also create full adders from half adders. The operations done by half adders and full adders above are the building blocks to computer operations and ALU logic.

Now that we have successfully evaluated the K-Map, we must talk about prime implicants. To solve this, we must circle all of the 1s on the K-Map, and evaluate the variables. There are a few rules about the circling that we can do on the K-Map.

  • The terms circled must be adjacent to eachother
  • Exclusive one bit type may be circled on the K-Map (1s or 0s)
  • The number of terms circled must be to a power of 2^n

The circled terms can be identified by their row and column. From the previous article, we discussed how the digits of the K-Map are just abstractions for variables. Therefore we can replace the variables with digits to make the future steps easier. The choice of digits is arbitrary, but I choose to notate the vertical bits under "A", and the horizontal bits under "BC". Additionally, we must take the minterms of each grid-input to fully represent all of the variable combinations.

  • Minterm 0's 1 has its value on column "0" and row "00"
  • Minterm 3's 1 has its value on column "0" and row "11"
  • Minterm 5's 1 has its value on column "1" and row "01"
  • Minterm 6's 1 has its value on column "1" and row "10"

The notations are variable A for columns, and variables BC for rows. To properly construct the minterm values from this, we must combine both the positionings from the columns and rows. For example, Minterm 0's term will have columns "0" and rows "00" (represented by ABC) as A'B'C'. This creates our first constructed minterm A'B'C'. From here, we can create a table for all values circled.

This new constructed list leaves only the values circled. Since there is only one term in each circle, we take the minterm for each value circled and put it into SoP (Sum of Product) form. This will leave us with our answer:

F = A'B'C' + A'BC + AB'C + ABC'

The expression below guarantees that for all the evaluations done in the function, the equation above is a valid result for all of them. We can check the validity of our claim by stating that each literal bit value is equal to the variable going down. For instance, Minterm 0 would have values A=0, B=0, C=0 since Mintern 0's literal is 000.

  • 0'0'0' + 0'00 + 00'0 + 000' = 1 (Minterm 0)
  • 0'1'1' + 0'11 + 01'1 + 011' = 1 (Minterm 3)
  • 1'0'1' + 1'01 + 10'1 + 101' = 1 (Minterm 5)
  • 1'1'0' + 1'10 + 11'0 + 110' = 1 (Minterm 6)
